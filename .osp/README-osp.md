# .osp для Laravel-проекта (адаптация full-example.local)

## Допущения, которые надо проверить первым делом

1. **Имя хоста — `tso.local`.** Если у вас другое, переименовать нужно в шести местах:
   три имени файлов (`nginx/tso.local.conf`, `apache/tso.local.conf`,
   `caddy/tso.local.conf`) и три заголовка секций (`project.ini`, `env.ini`,
   `tasks.ini`), плюс `category` и имена секций в `menu.ini` и строка `import common_host`
   в caddy-конфиге. Имя папки проекта должно совпадать с хостом.
2. **`{base_dir}` — это корень Laravel**, то есть папка, где лежит `artisan`.
   У вас раньше было `C:\OSPanel\domains\tso_client\admin` — то есть Laravel лежал в
   подпапке `admin`. Если структура сохранилась, везде замените `{base_dir}` на
   `{base_dir}\admin` (в `project_root`, `web_root`, `app_start_command`, `tasks.ini`,
   `menu.ini`, apache-конфиге). Либо — что чище — сделайте корнем проекта сам `admin`.
3. **PHP 8.5** жёстко задан в `php_engine`. `composer.json` требует `^8.5`
   и Laravel 12.

## Что изменено по сравнению с примером и почему

### project.ini

Убрана вторая секция (`shop.`) — у вас одно приложение. Публичный маркет — это
маршрут внутри того же Laravel, а не отдельный хост.

| Параметр | Было | Стало | Зачем |
|---|---|---|---|
| `project_root` | `{base_dir}\www` | `{base_dir}` | терминал и `osp project` должны открываться там, где `artisan` |
| `web_root` | `{base_dir}\www` | `{base_dir}\public` | в веб торчит только `public/`; иначе `.env` читается из браузера |
| `app_start_command` | пусто | `queue:work --queue=tso-tasks,tso-accounts,tso-market,default` | запуск фонового воркера для всех очередей приложения |
| `php_engine` | `auto` | `PHP-8.5` | версия должна быть воспроизводимой, а не «какая сейчас выбрана глобально» |
| `server_aliases` | `www.{host} alias-example.local` | `www.{host}` | чужой алиас из примера убран |
| `backend_port` | `3000` | `5173` | порт Vite, на случай если захотите проксировать HMR |

`backend_enabled` оставлен `off`: штатный сценарий Laravel + Vite — это `@vite` в блейде,
который сам ходит на `localhost:5173`. Прокси нужен только если захотите HMR через HTTPS.

### tasks.ini

Два пункта вместо трёх демонстрационных:

- **Queue worker watchdog** — сторож `osp project {host} start` с флагом `1 0` (одиночный
  экземпляр, скрытое окно) раз в минуту. Он проверяет, запущен ли процесс из
  `app_start_command` и перезапускает его в случае падения, не плодя дублей.
- **Laravel scheduler** — `tso:run-scheduler --work` ровно раз в минуту (`* * * * * 1 0`).
  Выполняет пересчёт задач, синхронизацию маркета, синхронизацию аккаунтов, ротацию логов
  и инлайн-обработку очереди с флагом одиночного экземпляра (1 0).

### menu.ini

Двенадцать пунктов быстрого доступа:

1. **«Прогнать все гейты»**: четыре команды из `AGENTS.md` одним кликом (`test`, `pint`, `phpstan`, `build`).
2. **Консоль проекта**: `osp project {host}` с показом версий PHP и Node.
3. **Запустить Vite (`npm run dev`)**: запуск dev-сервера фронтенда.
4. **Собрать фронтенд (`npm run build`)**: быстрая сборка ассетов.
5. **Перезапустить воркер очереди (`queue:restart`)**: сигнал воркеру на плавный перезапуск.
6. **Запустить воркер отладки (`queue:listen`)**: интерактивный воркер с live-reload кода без необходимости перезапускать очередь при правках.
7. **Сбросить кеши (`optimize:clear`)**: полная очистка кешей конфигов, маршрутов, представлений и кеша приложения.
8. **Выполнить миграции (`migrate`)**: применение новых миграций БД.
9. **Создать симлинк хранилища (`storage:link`)**: создание симлинка `public/storage`.
10. **Tinker**: интерактивная REPL-консоль Laravel.
11. **Смотреть `laravel.log` (`tail_log`)**: стриминг последних 200 строк логов с защитой от отсутствия файла.
12. **Создать резервную копию проекта**: архивация 7-Zip с исключением `vendor`, `node_modules`, `logs`, `.git`.

### env.ini — самая опасная часть

Оставлен пустым намеренно. `phpdotenv` в Laravel не перезаписывает уже существующие
переменные окружения. Если положить сюда `DB_DATABASE` или `APP_ENV`, они молча
перебьют `.env`, и отладка будет мучительной — файл `.env` будет выглядеть правильным,
а приложение будет видеть другое.

### Конфиги веб-серверов

В примере они меняли только `index`-файл. Здесь три вещи: фронт-контроллер
(`try_files ... /index.php`), запрет на точковые файлы и увеличенный размер тела запроса.
В caddy-варианте убран `browse` — листинг каталогов на Laravel-проекте не нужен.

Нужен только тот файл, который соответствует вашему `http_engine`. Остальные два можно
удалить — они лежат мёртвым грузом и расходятся при правках.

### public/.user.ini

Пример клал его в `www/`. Класть нужно в `public/` — `.user.ini` читается из каталога
скрипта, а не из корня проекта. И он **не влияет на CLI**: `queue:work` и `artisan`
берут лимиты из `php.ini` модуля PHP. Если тяжёлые задачи падают по памяти,
править надо именно `php.ini`, а не этот файл.

В примере было `error_reporting = E_ALL & E_NOTICE`. Это почти наверняка опечатка:
`&` даёт пересечение, то есть только `E_NOTICE`, а не «всё кроме notice» (для этого нужно
`E_ALL & ~E_NOTICE`). Заменено на `E_ALL`.

## Чего здесь нет и надо проверить руками

Проект на **PostgreSQL и Redis**, а не на MySQL. В OpenServer оба модуля есть, но по
умолчанию могут быть выключены, а расширения `pdo_pgsql` и `redis` — не активны в
выбранной сборке PHP. Это настраивается в настройках самого OpenServer, а не в `.osp`.
Проверка: `php -m` должна показать оба.

Также не забудьте `php artisan storage:link` — симлинки на Windows требуют запуска
от администратора либо включённого режима разработчика.

## Куда класть

```
<корень проекта>\
  .osp\           <- из архива
  public\
    .user.ini     <- из архива
  app\ artisan ...
```

`.osp\backup\` создастся сам при первом бэкапе. Добавьте в `.gitignore`:

```
/.osp/backup/
```

Сам `.osp/` в гит коммитить стоит — это воспроизводимая настройка окружения,
ровно такая же часть проекта, как `docker-compose.yml`. Но только при условии,
что `env.ini` остаётся без секретов.
