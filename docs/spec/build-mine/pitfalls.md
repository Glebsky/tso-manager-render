# Pitfalls: чего делать нельзя

Перечень основан на реальных особенностях этого проекта и игрового протокола.
Каждый пункт — запрет с указанием, что делать вместо него.

## 1. Не путать поле `type` в команде постройки с видом действия

Во всех существующих методах сервиса первый аргумент `buildServerAction()` — это
вид действия (`0`/`1` для производства). В команде `50` это **номер здания**.

- Неправильно: `buildServerAction(0, $grid, 0, null)` для команды `50`.
- Правильно: `buildServerAction($buildingNumber, $grid, 0, null)`.

Для команды `60` наоборот: первый аргумент строго `0`.

## 2. Не брать номер здания из payload задачи

Если номер приходит извне, устаревшая или подделанная задача сможет построить
любое здание в обход каталога. Номер всегда вычисляется во время исполнения из
имени руды в свежем снапшоте (ADR-13, INV-1).

## 3. Не доверять `payload['building_name']` и `payload['deposit_name']`

Это отображаемые подсказки для интерфейса и логов. Решение принимается только по
снапшоту зоны. Между планированием задачи и её исполнением могут пройти сутки.

## 4. Не использовать кэш зоны из модели аккаунта

`Account::$zone_data` может быть устаревшим. Постройка по устаревшим данным
тратит ресурсы и слот очереди. Всегда свежий снапшот (ADR-5).

## 5. Не копировать логику «свободного грида» из юзерскрипта буквально

В `user_drunken_miner.js:524` UI-список считает грид свободным при
`GetBuildingMode() === 1 || === 4`, а перед отправкой команды на строке `925`
требуется строго отсутствие здания. Это внутреннее противоречие исходного
скрипта, из-за которого часть строк его списка никогда не строится.

У нас единственный критерий — «на гриде нет никакого здания», и он один и тот же
в UI-списке и в обработчике (INV-4).

## 6. Не пропускать проверку очереди стройки

Без свободного слота команда либо отклоняется, либо ведёт себя непредсказуемо.
Если данных об очереди в снапшоте нет — считать, что свободных слотов ноль, и
отказывать (ADR-7). Не «на всякий случай отправить».

## 7. Не отправлять команды параллельно и не спать внутри обработчика

- Запрещено: `sleep(1)` внутри `handle()` — это блокирует воркер очереди.
- Запрещено: цикл по нескольким гридам внутри одного обработчика.
- Правильно: один грид на задачу, массовость через `sequence` с
  `delay_seconds >= 1` (ADR-6, FR-9).

## 8. Не сравнивать имена зданий без учёта регистра

В `icons.xml` соседствуют `IronMine` (id `50`) и устаревшее `Ironmine` (id `78`),
`GoldMine` (`46`) и `Goldmine` (`84`). Регистронезависимое сравнение или
`strtolower()` при поиске по каталогу может выбрать устаревшую запись и построить
не то здание. Сравнение строгое: `===`.

## 9. Не расширять каталог «попутно»

Epic, Arctic и Endless шахты имеют другие правила количества и механику
`depletedMineExtension`. Их id известны, но они намеренно вне объёма (INV-8).
Добавление их в конфиг без отдельной проверки — регрессия по безопасности.

## 10. Не пытаться апгрейдить не-шахты

Команда `60` универсальна, но `upgrade_mine` обязан отказывать, если здание не
найдено в каталоге шахт (ADR-11). Тип задачи должен честно описывать свои
полномочия.

## 11. Не забыть, что без правки парсера фича мертва

`storage/app/parse_zone.py` сейчас не извлекает ни залежи, ни очередь стройки.
Если выполнить только PHP-часть, политики будут стабильно отказывать по причинам
`no_deposit_at_grid` и `build_queue_full`, и это будет выглядеть как «фича не
работает». Шаг 1 плана обязателен и идёт первым.

## 12. Не менять сигнатуру `recursive_extract` частично

Функция вызывается рекурсивно из нескольких мест. Если добавить параметр
`deposits`, нужно обновить **все** рекурсивные вызовы внутри функции, иначе
Python упадёт с `TypeError` уже в рантайме, а не при разработке. Проверять
вызовы по всему файлу поиском `recursive_extract(`.

## 13. Не ломать существующий контракт снапшота зоны

Новые ключи `deposits` и `build_queue` только добавляются в итоговый словарь
результата. Существующие ключи (`buildings`, `specialists`, `resources`,
`pickups`, `errorCode` и остальные) переименовывать, переупорядочивать или
удалять нельзя: от них зависят другие функции (INV-5).

## 14. Не писать тексты в коде и в шаблоне Vue

Все строки результата, причин отказа и подписей интерфейса — через `lang` в трёх
локалях `en`, `ru`, `uk`. Пропущенный ключ в одной локали — это баг.

## 15. Не трактовать отказ политики как ошибку

Отказ — это успешный исход задачи с информативной строкой результата (ADR-12).
Исключение бросается только при `grid <= 0`, ошибке загрузки зоны и сессионных
кодах `1005`/`1012`.

## 16. Не расширять реестр обработчиков «умным» способом

`TaskHandlerRegistry` получает массив классов и выбирает первый, чей `supports()`
вернул `true`. Нужно добавить ровно две строки в существующий массив в
`TaskServiceProvider::register()`. Никаких автоматических сканирований каталога,
атрибутов или тегов контейнера.

## 17. Не путать две схемы нумерации типов залежей во фронтенде

`Tasks.vue:1505-1513` использует нумерацию с нуля (`0` — камень), а
`AccountDetail.vue:1297-1305` — с единицы (`1` — `FindDepositStone`). Это разные
схемы для разных задач. Для новой фичи номера типов залежей вообще не нужны:
используются имена руд из API. Не заводить третью схему.

## 18. Не читать кириллические файлы через терминал

Чтение `.md` и `.php` с кириллицей через PowerShell даёт мусор из-за кодовой
страницы консоли. Для чтения и записи использовать файловые инструменты, а не
конвейеры терминала.

## 19. Не увеличивать `phpstan-baseline.neon`

Новый код должен проходить статический анализ без добавления исключений. Появление
новых записей в baseline — повод исправить типы, а не расширить baseline.

## 20. Не оставлять кэш списков грязным после успешной команды

После успешной постройки или апгрейда список целей устарел. Обработчик обязан
вызвать `MineTargetListService::clearCache((int) $account->id)` — по образцу
`ClickableBuildingListService::clearCache()` в `CollectBuildingHandler`.

## Дополнение ревизии 2 (найдено при перепроверке плана по коду)

### 21. Не вставляй параметры перед `visited` в `recursive_extract`

Все рекурсивные вызовы в `storage/app/parse_zone.py` передают `visited`
позиционно. Новые параметры перед ним привяжут `set` к `deposits`, а `visited`
станет `None` — защита от циклов отключится, и на циклическом графе AMF будет
бесконечная рекурсия. Все шесть вызовов переводятся на `visited=visited`.
Проверка: `recursive_extract(` должно встречаться в файле ровно 7 раз, и в шести
из них обязаны быть `deposits, build_queue`.

### 22. Не изобретай имена полей очереди стройки

`GetQueue_vector()` и `GetTotalAvailableSlots()` из юзерскрипта — методы
клиентской модели, а не поля серверного VO. Ветка `dPlayerVO` в парсере читает
атрибуты по белому списку, поэтому «добавить рядом» недостаточно. Сначала
разведка фактических имён (implementation-plan §1.0), потом код. Ветка с
выдуманным именем даст `total = 0`, вся фича молча уйдёт в отказы
`build_queue_full`, и это будет выглядеть как ошибка логики, а не как ошибка
парсера.

### 23. Добавление case в `TaskType` ломает существующие тесты

`tests/Unit/EnumsTest.php`, `tests/Unit/TaskHandlerRegistryTest.php` и
`tests/Feature/ApiContractTest.php` перечисляют типы задач. Их правка — часть
шага 2, а не «неожиданное падение» на финальном гейте. Ни один существующий
ожидаемый тип не удалять.

### 24. `supports()` — обязательный метод обработчика

`TaskActionHandlerInterface` требует и `supports(string $actionType): bool`, и
`handle(Account $account, array $payload): string`. Без `supports()` класс не
скомпилируется, а реестр его не найдёт.

### 25. `extractErrorCode()` никогда не возвращает `null`

Он возвращает `int` и при исключении разбора отдаёт `0`, то есть сбой выглядит
как успех. Проверку `!== null` не писать (мёртвый код). В `catch` добавить
`Log::warning`, чтобы неразобранные ответы были видны. Контракт метода в
`CollectBuildingHandler` в рамках этой задачи не менять.

### 26. Зона грузится двумя вызовами

`$this->amf->getZone($account)` возвращает сырой AMF, и только затем
`$this->zones->parse($zoneAmf)` даёт массив. Метода «загрузить зону» в
`ZoneParserService` нет.

### 27. Не добавляй типы шахт в существующий `in_array` внутри `sequenceRules()`

Тот блок навязывает шагу правило `payload.mode` со значениями
`auto,collectible,quest_trigger` — это набор сбора зданий, к шахтам он
отношения не имеет. Для шахт делается отдельный `if` в том же `foreach`.

### 28. В `buildings` бывают строки, а не только массивы

`make_serializable()` подставляет заглушки вида `<circular reference to ...>`.
Перед обращением к элементу — `is_array()`, как это делает
`CollectBuildingHandler`.

### 29. Байтовые строки из AMF

`str(b'IronOre')` даёт `"b'IronOre'"`, и сверка с ключами каталога перестаёт
работать при регистрозависимом сравнении (pitfall 8). Байты декодировать явно:
`value.decode('utf-8', errors='replace')`.

### 30. Компонент выбора цели уже существует

`resources/js/components/tasks/BuildingPicker.vue` — готовый выбор цели по гриду.
Новую модалку внутри `Tasks.vue` не писать: либо расширить его пропсами, либо
сделать рядом однотипный `MineTargetPicker.vue`.

## 31. Бросать исключение после отправки необратимой команды

Самая дорогая ошибка во всей задаче. `ActionRetryPolicy` перехватывает
`GameServerErrorException` и вызывает обработчик заново до трёх раз при кодах
`1005` и `1012`. Код в ответе не означает, что команда не выполнилась. Для
`stop_production` повтор безвреден, для команд `50` и `60` — это вторая
постройка и повторно списанные ресурсы.

Правило: в обработчиках шахт исключения допустимы только до отправки команды.
После отправки — всегда `return` строки, каким бы ни был код ответа.
См. `implementation-plan.md` Р3-1.

## 32. Расчёт на то, что повторный снапшот увидит постройку

«Второй проход всё равно увидит `grid_occupied`» — неверно. Свежая постройка
сначала стоит в очереди стройки, здания на гриде ещё нет. Занятость грида надо
проверять и по очереди тоже, если в дампе есть гриды её элементов (Р3-2).

## 33. Возврат сырого AMF из обработчика

`GameResponseValidator::validateAndParse()` применяется к строке, которую вернул
обработчик. Если вернуть `$rawAmf`, валидатор разберёт его и бросит исключение —
и включится повтор из пункта 31. Возвращать только локализованный текст, без
подстрок `errorCode` и `_amf_response`.

## 34. Ожидание, что упавший шаг остановит последовательность

Не остановит. `executeInlineSequence()` ловит `Throwable` каждого шага и
продолжает цикл. Пакет из шести построек отправит все шесть команд независимо от
сбоев. Учитывать при проектировании UI пакетного режима.

## 35. Дробная задержка между шагами

`delay_seconds` приводится через `(int)` и уходит в `sleep()`. Значения вида
`0.5` дадут `0`, то есть отсутствие задержки. Минимум — `1`.

## 36. Попытка вызвать buildServerAction из шлюза

`buildServerAction()` и `sendServerCall()` в `TsoAmfService` приватные. Новые
методы должны быть внутри этого класса, шлюз только делегирует.
