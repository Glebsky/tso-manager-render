## 0. ЧИТАЙ ЭТО ПЕРВЫМ, ЕСЛИ ТЫ АГЕНТ-ИСПОЛНИТЕЛЬ

Ты будешь реализовывать эту спеку. Прочитай раздел целиком, прежде чем писать хоть строчку кода.

### 0.1. Что уже сделано (не переделывай)

Фича «очередь производства бафов» **уже реализована и работает**. Есть:

- команда `php artisan tso:import-production-catalog`, которая генерирует `config/game_production.php`;
- сервис `ConfigProductionCatalog`, DTO `ProductionRecipe`, `ProducerBuilding`;
- обработчик задач `ProduceBuffHandler`, AMF-команда 91, эндпоинт `GET /api/game/buff-producers`;
- Vue-компонент `ProducerPicker.vue`.

**Всё это остаётся. Ты только расширяешь импортёр каталога новыми источниками рецептов.**

### 0.2. Какую именно проблему ты чинишь

Пользователь открывает мастерскую в UI и видит:

> «Для этой мастерской нет доступных рецептов»

Это происходит для **Переплётчика, Казарм и Ратуши**, хотя в игре рецепты у них есть.

**Причина (диагноз подтверждён, не оспаривай его):** импортёр каталога умеет читать рецепты только из двух мест:

1. `explicit_list` — непустые узлы `<TimedProductionList id="N">` в globals-XML;
2. `buff_pool` — глобальный пул `<Buff produceable="true">`.

Но **девять** списков `<TimedProductionList>` в XML **пусты намеренно** — их содержимое клиент собирает из совершенно других файлов и структур. Список пуст ≠ рецептов нет. Пустой список — это указатель «ищи данные в другом месте».

### 0.3. Твоя задача одним предложением

Научить импортёр каталога собирать рецепты из **пяти новых источников** данных, чтобы каждое здание-производитель в UI показывало непустой список рецептов, и закрепить это автоматическим тестом покрытия.

## 1. Иерархия источников истины

Когда два источника противоречат друг другу, побеждает тот, что выше. Это правило абсолютное.

| Ранг | Источник | Почему |
| --- | --- | --- |
| 1 | **Живой трафик AMF** (дампы реальных запросов/ответов игры) | Это то, что сервер реально принял и вернул. Спорить не с чем |
| 2 | **Декомпилированный клиент** `client_scripts.txt` | Показывает точный алгоритм. Но клиент может не отражать серверные проверки |
| 3 | **Игровые XML** (этот архив) | Данные, на которых работает клиент. Могут содержать неиспользуемые/устаревшие узлы |
| 4 | **Userscripts** сторонних авторов | Полезные подсказки, но авторы тоже угадывали |
| 5 | Догадки, аналогии, «логично же» | **Запрещено использовать как основание.** Только как гипотезу с пометкой OQ |

**Правило для агента:** если ты не можешь сослаться на источник ранга 1–3, ты не «знаешь» — ты «предполагаешь». Предположение оформляется как открытый вопрос в `open-questions.md`, а не как код.

## 2. Границы задачи (scope)

### 2.1. Входит

- Расширение `ImportProductionCatalog` пятью новыми источниками рецептов.
- Расширение схемы `config/game_production.php` (обратно совместимо).
- Расширение DTO `ProductionRecipe` полями, которых требуют новые источники.
- Тест покрытия каталога `CatalogCoverageTest`.
- Обновление UI-подсказок там, где рецепт нельзя заказать.

### 2.2. НЕ входит

- Изменение AMF-протокола. Команда 91 и `dTimedProductionVO` остаются как есть.
- Изменение логики планировщика задач.
- Реализация типа 7 (Combat 3 Units) — вынесено в открытые вопросы, см. `open-questions.md` OQ-7.
- Реализация типа 3 (Effects) — **у типа 3 вообще нет здания-производителя**, см. `recipe-source-matrix.md` §4.
- Перевод названий рецептов на русский — отдельная задача (данные для неё есть, см. `data-sources.md` §5).

### 2.3. Явные запреты

1. **Не удаляй** существующие источники `explicit_list` и `buff_pool`.
2. **Не хардкодь** списки рецептов в PHP-коде. Всё берётся из XML на этапе импорта.
3. **Не «чини»** пустые `<TimedProductionList>` дописыванием туда рецептов вручную. Это исходные данные игры, они read-only.
4. **Не меняй** `config/game.php`. Каталог живёт в `config/game_production.php`.
5. **Не запускай** PHP-инструменты вне проекта — в песочнице PHP отсутствует.

## 3. Определение готовности (Definition of Done)

Задача считается выполненной, когда **все** пункты истинны:

- [ ] `php artisan tso:import-production-catalog` отрабатывает без ошибок и предупреждений.
- [ ] В `config/game_production.php` ключ `recipes` содержит непустые группы для типов **0, 1, 2, 4, 5, 6, 8, 11** и всех ранее работавших.
- [ ] `CatalogCoverageTest` зелёный: для каждого `productionType` из `producers` либо есть рецепты, либо есть явная запись об осознанно неподдерживаемом источнике.
- [ ] В UI Переплётчик показывает 3 рецепта (Manuscript, Tome, Codex).
- [ ] В UI Казармы показывают 9 рецептов, Элитные казармы — 7.
- [ ] В UI Ратуша показывает коллекции (число зависит от активных событий, см. `verification.md`).
- [ ] `php artisan test` — все тесты проходят.
- [ ] `./vendor/bin/pint --test` — без замечаний.
- [ ] `./vendor/bin/phpstan analyse` — No errors.
- [ ] `npm run build` — успешно.
- [ ] Создан `walkthrough.md` с описанием того, что сделано.

## 4. Как задавать вопросы

Если по ходу работы ты понимаешь, что данных не хватает:

1. Проверь `open-questions.md` — возможно, вопрос уже зафиксирован и у него есть обходной путь.
2. Если вопроса там нет — **останавливайся, не выдумывай**. Добавь новый OQ и спроси человека.
3. Никогда не закрывай пробел в данных заглушкой, которая выглядит как рабочий код. Заглушка обязана явно падать или явно логировать «источник не поддерживается».
