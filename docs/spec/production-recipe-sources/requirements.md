# Requirements

Нотация: **FR** — функциональное требование, **NFR** — нефункциональное, **AC** — критерий приёмки, **INV** — инвариант (должен выполняться всегда).

Каждый AC обязан иметь автотест. Соответствие AC ↔ тест — в `verification.md`.

---

## 1. Функциональные требования

### Группа A — источники рецептов

| ID | Требование |
| --- | --- |
| **FR-1** | Импортёр каталога обязан поддерживать шесть источников: `explicit_list`, `buff_pool`, `buff_group`, `military_units`, `skillpoints`, `collections`, плюс служебный `unsupported:<reason>`. |
| **FR-2** | Соответствие `productionType → источник` задаётся **декларативной картой** в одном месте, а не цепочкой `if`/`switch`, размазанной по коду. |
| **FR-3** | Тип 0 получает ровно 9 рецептов из `<MilitaryUnit produceable="true">` без `isElite`. |
| **FR-4** | Тип 8 получает ровно 7 рецептов из `<MilitaryUnit produceable="true" isElite="true">`. |
| **FR-5** | Тип 2 получает ровно 3 рецепта из `<skillPoint>`. |
| **FR-6** | Тип 4 получает ровно 16 рецептов из `<collection>`. |
| **FR-7** | Тип 6 получает бафы с `group="5"`; тип 11 — с `group="11"`. Соответствие задано картой `buff_group_map`, а не вычислением. |
| **FR-8** | Тип 7 помечается `unsupported:needs_tier_data` с пустым списком рецептов. |
| **FR-9** | Пустой `<TimedProductionList>` с id из множества {0,1,2,3,4,6,7,8,11} НЕ считается ошибкой и НЕ порождает предупреждений. |
| **FR-10** | Пустой список с любым ДРУГИМ id — это предупреждение в лог импорта. |

### Группа B — стоимость и время

| ID | Требование |
| --- | --- |
| **FR-11** | Каждый рецепт имеет `duration_seconds` — целое число секунд, нормализованное из трёх разных атрибутов (`productionTime`, `duration`, `productionTimeSeconds`). |
| **FR-12** | Каждый рецепт имеет `costs: list<{resource, count}>` и булев `costs_known`. |
| **FR-13** | Ресурс `Population` помечается флагом `is_population` и не проверяется по остаткам склада. |
| **FR-14** | Для типа 2 в рецепт пишутся все ценовые уровни в `cost_tiers`, а `cost_is_lower_bound = true`. |
| **FR-15** | UI при `cost_is_lower_bound = true` показывает стоимость с приставкой «от» и поясняющей подсказкой. |
| **FR-16** | Суммарная стоимость заказа = `costs × amount × stacks`; суммарное время = `duration_seconds × amount × stacks`. |

### Группа C — лимиты и политика

| ID | Требование |
| --- | --- |
| **FR-17** | Глобальные лимиты: `amount ≤ 25`, `stacks ≤ 200`. |
| **FR-18** | Для типа 2 лимиты переопределяются: `amount = 1`, `stacks = 1`. |
| **FR-19** | Политика заказа получает новые причины отказа: `production_type_unsupported`, `recipe_requires_inactive_event`, `amount_exceeds_recipe_limit`. |
| **FR-20** | Причина отказа обязательно доходит до UI и лога активности. Молчаливый отказ запрещён. |

### Группа D — UI

| ID | Требование |
| --- | --- |
| **FR-21** | При выборе здания с `recipe_source = unsupported:*` UI показывает **«Поддержка этого здания ещё не реализована»**, а НЕ «Нет доступных рецептов». |
| **FR-22** | «Нет доступных рецептов» показывается только тогда, когда каталог непуст, но все рецепты отфильтрованы требованиями игрока. |
| **FR-23** | Все новые строки добавляются в `lang/en`, `lang/ru`, `lang/uk` одновременно. |
| **FR-24** | Для типа 2 слайдеры количества скрыты или заблокированы на значении 1. |

### Группа E — референсы

| ID | Требование |
| --- | --- |
| **FR-25** | Архив XML кладётся в `docs/references/xml/` с сохранением исходного `README.md`. |
| **FR-26** | `docs/references/README.md` получает таблицу соответствия старых и новых файлов. |
| **FR-27** | Пути к XML передаются опциями команды; при их отсутствии файл определяется по корневому тегу и маркерному узлу, а НЕ по имени с хэшем. |

## 2. Нефункциональные требования

| ID | Требование |
| --- | --- |
| **NFR-1** | PHP 8.5. Авторитетный документ — `docs/spec/constitution.md`. Файл `laravel-constitution.md` устарел. |
| **NFR-2** | Гейты обязательны и все должны быть зелёными: `php artisan test`, `vendor/bin/pint --test`, `vendor/bin/phpstan`, `npm run build`. |
| **NFR-3** | Ни один существующий тест не должен сломаться. Базовая линия — 294 passed / 1725 assertions. |
| **NFR-4** | Импорт каталога должен оставаться оффлайн-операцией: чтение файлов с диска, без сети. |
| **NFR-5** | Файл `config/game_production.php` остаётся единственным выходом импортёра. Не дробить на несколько файлов. |
| **NFR-6** | Парсинг XML — только XML-парсером. Regex по игровым XML запрещён. |
| **NFR-7** | Время импорта не более 60 секунд на типичной машине разработчика. |
| **NFR-8** | Размер `config/game_production.php` не более 2 МБ. Сейчас 798 КБ; рост ожидается небольшой. |

## 3. Инварианты

| ID | Инвариант |
| --- | --- |
| **INV-1** | `type_string`, отправляемый в команде 91, всегда равен `recipe.name` из каталога. Никаких преобразований регистра, переводов, тримов. |
| **INV-2** | `productionType` в запросе всегда равен `productionType` выбранного здания из ICONS. |
| **INV-3** | Очередь производства привязана к `productionType`, а не к гриду здания. |
| **INV-4** | `production_queues = null` означает «данные недоступны», `[]` означает «очередь пуста». Это разные состояния. |
| **INV-5** | Каталог общий для всех аккаунтов. Персональная доступность проверяется только в рантайме по снапшоту зоны. |
| **INV-6** | Каталог покрывает все 69 типов из ICONS: у каждого либо непустой список рецептов, либо явный `unsupported:*`. Третьего не дано. |

**INV-6 — главный инвариант всей задачи.** Именно его нарушение привело к багу «Нет доступных рецептов».

## 5. Что НЕ является требованием

Явно исключено из этой задачи, чтобы агент не расширял scope самовольно:

1. Локализация имён рецептов из `localization_oasis.xml` — отдельная задача.
2. Мгновенное завершение производства за самоцветы — отдельная задача (команда `BUY_ONE_CLICK_SHOP_ITEM`).
3. Отмена и перестановка заказов в очереди (команды 1025–1030) — отдельная задача.
4. Поддержка `stacks > 1` в UI — заблокирована до закрытия F-4.
5. Тип 7 — заблокирован до закрытия OQ-7.
6. Эпические мастерские (`epic_workyard/`) — другая механика, вне scope.
7. Магазин, ачивки, квесты — вне scope.
