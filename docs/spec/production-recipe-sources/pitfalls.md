# Pitfalls — ловушки

Каждый пункт ниже — это ошибка, которую **уже кто-то совершил** при работе над этим проектом — человек или агент. Не повторяй их.

Нумерация продолжает пакет `buff-production-queue` (там были P-1…P-28).

---

## Категория 1: парсинг XML

### P-29. Три разных имени для длительности

Атрибут называется `duration`, `productionTime` или `productionTimeSeconds` — в зависимости от узла.

**Симптом ошибки:** все военные юниты получают `duration_seconds = 0`, в UI пишется «0 сек».

**Лечение:** `DurationNormalizer` из `design.md` §6.

### P-30. Девять пустых списков — это норма

Списки 0, 1, 2, 3, 4, 6, 7, 8, 11 пусты по замыслу разработчиков игры.

**Симптом ошибки № 1:** импортёр падает или спамит варнингами.
**Симптом ошибки № 2 (именно это и произошло):** импортёр молча пропускает эти типы, пользователь видит «Нет доступных рецептов», все 294 теста при этом зелёные.

**Лечение:** инвариант INV-6 и тест `CatalogCoverageTest`.

### P-31. Закомментированный пример в файле коллекций

В шапке `collectibles_and_loot.xml` лежит шаблон-пример `<collection name="CountrySaying" …>` внутри XML-комментария.

**Симптом:** получаешь 17 коллекций вместо 16, и в UI появляется несуществующий рецепт.

**Лечение:** только XML-парсер (NFR-6). Regex запрещён.

### P-32. Жадная регулярка на закрывающем теге

Если всё же используешь регулярки для разведки (не для прода): `<TimedProductionList id="N">.*?</TimedProductionList>` с точкой-любой-символ даёт ложные нули.

**Лечение:** искать конец через `find('</TimedProductionList>', match.end())`.

### P-33. 51 баф без блока `<Costs>`

Из 299 производимых бафов у 248 есть стоимость, у 51 — нет.

**НЕ удаляй их из каталога.** Они производимы. Просто ставь `costs_known = false` и показывай в UI «Стоимость неизвестна». Это уже работает в текущем коде — не сломай.

### P-34. Забытый фильтр `produceable="true"`

**Симптом:** 2916 бафов вместо 299, или 379 юнитов вместо 16. Конфиг раздувается до десятков мегабайт, сервер отвечает ошибкой на половину заказов.

## Категория 2: имена и регистр

### P-35. `InstantBuildCosts` с заглавной I

Только у `<collection>`. У всех остальных — `instantBuildCosts` или `instantFinishCost`.

**Симптом:** у всех коллекций `instant_finish_cost = null`. Тихая ошибка, тесты не падают.

### P-36. `<cost>` против `<Cost>` против `<resource>`

Три разных тега стоимости, два разных атрибута количества (`count` и `amount`). См. `evidence.md` §7.

XML чувствителен к регистру. `$el->Cost` и `$el->cost` — разные вещи.

### P-37. `type` против `name` против `id`

| Узел | Откуда берётся `type_string` |
| --- | --- |
| `<Buff>` | `name` |
| `<TimedProduction>` | `name` |
| `<MilitaryUnit>` | **`type`** |
| `<skillPoint>` | **`id`** |
| `<collection>` | `name` |

У `<MilitaryUnit>` есть и `id` (число), и `type` (строка). Если отправишь `id` — сервер вернёт ошибку, а клиент покажет пустой заказ.

### P-38. Юнит `EliteSoldier` не является элитным

`EliteSoldier` (id 7) идёт в тип 0, а не 8, потому что у него нет атрибута `isElite`.

**Запрещено:** фильтровать по подстроке `Elite` в имени. Только по атрибуту.

## Категория 3: архитектурные ловушки

### P-39. Номер группы ≠ номер типа

Для типа 11 нужна группа 11 — совпадает. Для типа 6 нужна группа **5** — не совпадает.

**Запрещено:** `$group = $productionType`. Только явная карта `buff_group_map`.

### P-40. Попытка создать новые типы таски

Кажется логичным сделать `TaskType::ProduceUnit`, `TaskType::ProduceSkillPoint` и т. д.

**НЕ ДЕЛАЙ.** Все типы производства шлют одну и ту же команду 91 с одним и тем же VO. Различаются только данные. Один `TaskType::ProduceBuff`, один хэндлер. См. `evidence.md` §2.

Да, имя `ProduceBuff` неточно описывает производство рекрутов. Переименование сломает существующие записи в базе. Живём с этим именем.

### P-41. Зелёные тесты не значат, что фича работает

Предыдущий агент получил 294 passed / 1725 assertions, phpstan чистый, pint чистый, сборка ок. И при этом три здания в проде не работали.

**Причина:** тесты проверяли то, что реализовано, а не то, что требовалось.

**Лечение:** тест покрытия (`CatalogCoverageTest`), который итерируется по всем 69 типам из ICONS, а не по тем, что есть в конфиге. Это разные множества, и в этом весь смысл.

### P-42. Очередь привязана к типу, а не к зданию

Гипотеза «у каждого здания своя очередь» была опровергнута трафиком: `buildingGrid = 0` в снапшоте.

Поле `meta.shares_queue_with` существует именно поэтому. Не удаляй его как «лишнее».

### P-43. Имена файлов с хэшами меняются

`gfx_settings_a742ef6a.xml` превратится в другое имя при следующем патче игры.

**Запрещено:** зашивать имена в код или в тесты. См. `data-sources.md` §2.

### P-44. Перепарсинг 4.5 МБ шесть раз

Если каждый источник откроет GLOBALS сам — импорт займёт минуты и съест гигабайты.

**Лечение:** загрузчик читает каждый файл ровно один раз и передаёт разобранные структуры в конструкторы источников.

## Категория 4: логика домена

### P-45. Прогрессивная цена очков навыков

`amountProduced` — это **порог**, а не количество на выходе.

**Симптом ошибки:** интерпретируешь `amountProduced="0"` как «производится 0 штук» и пропускаешь рецепт как невалидный.

### P-46. Стоимость очка навыка нельзя показать как точную

Мы не знаем, сколько игрок уже произвёл (OQ-2). Показываем нижнюю границу с пометкой.

### P-47. `collectedTime` — не метка времени

Это длительность в миллисекундах. Доказательство — `evidence.md` §6.

**Симптом ошибки:** считаешь время завершения как `collectedTime + duration` и получаешь 1970 год.

### P-48. Два слоя фильтрации нельзя смешивать

Каталог — что есть в игре. Снапшот — что доступно игроку. Не пытайся вычислить второе на этапе импорта — каталог общий для всех аккаунтов (INV-5).

### P-49. `Population` — не товар

Его нет на складе. Если проверять его по остаткам ресурсов, все заказы юнитов будут отклоняться с «недостаточно ресурсов».

## Категория 5: процесс

### P-50. Молчаливый отказ политики

Старый техдолг: политика отклоняет заказ, причина не доходит до UI. Пользователь видит «ничего не произошло».

Именно так и выглядел баг с «Корзинкой тётушки Ирмы»: пользователь выбрал рецепт, нажал добавить, и ничего не произошло без объяснений. FR-20 закрывает это.

### P-51. Расширение scope без спроса

Список того, что выглядит заманчиво, но запрещено — в `requirements.md` §5. Особенно соблазнительна локализация из `localization_oasis.xml` — файл лежит рядом, и кажется, что это пять минут работы. Это не пять минут — 8.1 МБ и собственная схема ключей.

### P-52. Удаление старых референсов

Не удаляй `docs/references/globals.xml` и `icons.xml`. На них ссылаются старые спеки и фикстуры тестов. Добавляй новое рядом и фиксируй соответствие в README.

### P-53. Параллельная запись в один файл

При работе субагентами: два агента, пишущие в `config/game_production.php` или в `ImportProductionCatalog.php` одновременно, гарантированно потеряют часть изменений.

Этапы A–F в `implementation-plan.md` специально разведены так, чтобы каждый трогал свой набор файлов. Соблюдай порядок.

### P-54. Гадание вместо вопроса

Если данных нет ни в трафике, ни в клиенте, ни в XML — **остановись и задай вопрос**. Не придумывай правдоподобное значение.

История проекта знает минимум три гипотезы, которые выглядели очень логично и оказались неверными: фильтр по `uiType`, разделение юнитов по `playerLevel`, ветвление через `isHardcoded`.
