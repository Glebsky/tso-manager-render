# Changelog v1.0 → v1.1

Основание: ответы владельца продукта на четыре открытых вопроса плюс доразведка XML-архива.

---

## Изменение 1 — тип 7 реализуется (крупное)

**Было:** `7 → unsupported:needs_tier_data`, 0 рецептов, OQ-7 открыт.

**Стало:** `7 → combat3_units`, 7 рецептов, OQ-7 закрыт.

**Почему это стало возможным.** В v1.0 файл `settings/game_units.xml` был отклассифицирован как ненужный, потому что поиск вёлся по тегу `<MilitaryUnit>`, а там тег `<Unit>`. Повторный обход по корневым тегам его нашёл. Это тот самый `cMilitaryUnitData`, ради которого был открыт OQ-7.

**Урок.** Перечислять файлы надо по корневому тегу и полному списку тегов, а не грепать по ожидаемому имени тега. Отсутствие совпадения не доказывает отсутствие данных.

Затронуты: `recipe-source-matrix.md`, `data-sources.md`, `design.md`, `requirements.md`, `implementation-plan.md`, `verification.md`, `open-questions.md`, `README.md`.

## Изменение 2 — политика стеков (среднее)

**Было:** единые лимиты 25/200 для всех рецептов.

**Стало:** лимиты остаются потолками, но появляется поле `stacks_supported` и конфиг-блок `stacks`.

**Почему.** Владелец указал два здания без стеков: Переплётчик (тип 2) и Рождественская пекарня (тип 27). Для типа 2 объяснение есть в коде клиента. Для типа 27 — только гипотеза H-1 про `culturebuilding`, поэтому решение вынесено в конфиг, а не зашито в код.

Затронуты: `design.md`, `requirements.md`, `verification.md`, `implementation-plan.md` (новый этап H), `pitfalls.md`.

## Изменение 3 — локализация явно вне scope (малое)

Переводы в проекте уже есть. Значит, `loca/localization_oasis.xml` (8.1 МБ) НЕ парсится вообще, и это теперь записано явно в границах scope, а не подразумевается. Агент добавляет только недостающие ключи во все три локали.
