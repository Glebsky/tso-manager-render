# Requirements: Мультивыбор зданий и специалистов в Task Planner

## Контекст и Проблема

Ранее в планировщике задач (**Task Planner**) пользователь мог выбрать только 1 здание или 1 специалиста при добавлении шага. Для применения одного и того же бафа к 10 зданиям или отправки 5 геологов пользователю приходилось вручную повторять процесс создания действия 10 или 5 раз соответственно. Кроме того, время задержки сбрасывалось на 5 секунд после каждого добавленного действия, новые задачи добавлялись в конец списка, а ошибки сервера выводились без человекочитаемого перевода.

## Цели

1. Ускорить процесс создания типовых групповых задач в Task Planner.
2. Предоставить пользователю возможность выбирать сразу несколько зданий (из своего города или города выбранного друга) и специалистов за один раз.
3. Переключать выбор зоны («Моя зона» / «Зона друга») прямо в форме с авто-загрузкой зданий выбранного друга.
4. Сохранять установленное время задержки (`stepDelay`) после добавления шагов.
5. Выводить новые задачи вверху списка Scheduled Tasks (`id desc`).
6. Отображать игровые ошибки человекочитаемым текстом на языке активного интерфейса (English / Русский).
7. Сохранить существующую backend-модель исполнения задач (`ScheduledTask` и `TaskExecutionService`) без фрагментации API.

---

## Требования

### Функциональные требования (FR)

- **FR-1: Переключатель зон «Моя зона» / «Зона друга»**
  - В форме шага находятся кнопки «Моя зона» и «Зона друга».
  - При выборе «Моя зона» скрывается селект с выбором друга, кнопка «Выбрать здания» открывает острова владельца.
  - При выборе «Зона друга» становится видимым селектор выбора друга; после выбора друга активируется кнопка «Выбрать здания друга».

- **FR-2: Множественный выбор зданий**
  - Пользователь может отметить одно или несколько зданий в модальном окне.
  - Модальное окно зданий избавлено от табов выборки зон, поддерживает закрытие по крестику (❌), клику на оверлей и клавише ESC.
  - Поддерживается фильтрация по категориям, поиск и быстрая кнопка «Выбрать все visible» / «Снять выбор».

- **FR-3: Множественный выбор специалистов**
  - Пользователь может выбрать нескольких специалистов (геологов или исследователей) для массовой отправки.
  - Модальное окно специалистов поддерживает фильтрацию, поиск и выбор всех visible элементов.

- **FR-4: Одиночный выбор бафа**
  - За один раз выбирается строго один баф. Множественный выбор бафов не допускается.

- **FR-5: Сохранение времени задержки (`stepDelay`)**
  - Значение задержки `stepDelay` в форме не сбрасывается к 5 секундам при добавлении действия, сохраняя значение для создания последующих шагов.

- **FR-6: Разворачивание множественного выбора в действия**
  - При клике «Добавить шаг» система создает $N$ независимых элементов в массиве `sequenceActions`.
  - Каждое действие содержит уникальную цель (конкретную сетку здания/специалиста) и копирует параметры шага (баф, задержка).

- **FR-7: Сортировка задач (новые сверху)**
  - Задачи выводятся в списке Scheduled Tasks по убыванию ID (`id desc`), помещая вновь созданные задачи наверх.

- **FR-8: Локализация ошибок сервера (English / Русский)**
  - Ошибки игрового сервера декодируются через `GameErrorResolver` и локализуются в `lang/en/ui.php` и `lang/ru/ui.php`.
  - Фронтенд отображает переведенное сообщение об ошибке в соответствии с текущей локалью пользователя.

- **FR-9: Асинхронное / Отложенное выполнение задач и polling**
  - Эндпоинт `POST /api/tasks/{task}/execute` не блокирует HTTP-запрос на длительное время (убирается жесткое ограничение в 60 секунд). Запуск переводится на отложенную очередь `ExecuteScheduledTaskJob`.
  - При запуске кнопка мгновенно переходит в состояние загрузки (спиннер).
  - Фронтенд выполняет периодический опрос состояния задачи (polling раз в 2 секунды). При завершении выполнения спиннер останавливается, и пользователю выводится итоговый нотификационный тост (успех или ошибка).

---

## Инварианты (INV)

- **INV-1**: Формат хранения и выполнения задач в базе данных (`scheduled_tasks.payload.actions`) не меняется. Каждое действие в `actions` является атомарным.
- **INV-2**: Исполнитель задач (`TaskExecutionService`) выполняет действия последовательно с учетом задержки.
- **INV-3**: Существующие задачи читаются и редактируются без сбоев.

---

## Acceptance Criteria (AC)

1. **AC-1**: Пользователь переключает зону на «Зона друга», выбирает друга, выбирает 3 его здания, добавляет шаг и получает 3 действия с `target_scope: 'friend'` и данными друга.
2. **AC-2**: Модальное окно закрывается при клике на крестик (❌), на темный оверлей вокруг окна или по клавише ESC.
3. **AC-3**: Указав задержку 15 секунд и добавив шаг, значение задержки в поле остается 15 секунд.
4. **AC-4**: Созданная задача отображается на первой позиции в списке задач аккаунта.
5. **AC-5**: При возникновении ошибки сервера (например, код 550) в русскоязычном интерфейсе отображается «Передано недопустимое значение», а в англоязычном — «Invalid value provided».
6. **AC-6**: При клике на ручной запуск задачи API возвращает быструю регистрацию выполнения, на кнопке крутится спинер, фронтенд запрашивает статус раз в 2 секунды и показывает итоговое сообщение после завершения длительной серии действий.
