# Requirements: Мультивыбор зданий и специалистов в Task Planner

## Контекст и Проблема

Ранее в планировщике задач (**Task Planner**) пользователь мог выбрать только 1 здание или 1 специалиста при добавлении шага. Для применения одного и того же бафа к 10 зданиям или отправки 5 геологов пользователю приходилось вручную повторять процесс создания действия 10 или 5 раз соответственно.

## Цели

1. Ускорить процесс создания типовых групповых задач в Task Planner.
2. Предоставить пользователю возможность выбирать сразу несколько зданий (из своего города и/или городов друзей) и специалистов за один раз.
3. Сохранить существующую backend-модель исполнения задач (`ScheduledTask` и `TaskExecutionService`) без изменений.

---

## Требования

### Функциональные требования (FR)

- **FR-1: Множественный выбор собственных зданий**
  - Пользователь может выбрать одно или несколько зданий на своем острове.
  - Поддерживается фильтрация по категориям и поиск по названию/сетке.
  - Доступна кнопка быстрых операций (выбрать все / снять выбор).

- **FR-2: Множественный выбор зданий друзей**
  - Пользователь может выбрать одного или нескольких друзей и выделить их здания.
  - Допускается **одновременный выбор** зданий со своего острова и зданий с островов друзей в один набор целей.
  - Каждое здание сохраняет привязку к своему владельцу (`target_scope: 'self'` или `target_scope: 'friend'`).

- **FR-3: Множественный выбор специалистов**
  - Пользователь может выбрать нескольких специалистов (геологов или исследовательских геонавтов/разведчиков) для массовой отправки.
  - Фильтрация по типу специалиста и поиск по имени/типу.

- **FR-4: Одиночный выбор бафа**
  - За один раз выбирается строго **один баф**. Множественный выбор бафов не допускается.

- **FR-5: Разворачивание множественного выбора в действия**
  - При нажатии кнопки "Добавить шаг" (или при создании задачи) система берет выбранный набор целей ($N$ зданий или $M$ специалистов) и генерирует $N$ или $M$ отдельных действий в массив `sequenceActions`.
  - Каждое сгенерированное действие содержит индивидуальную целевую сущность (конкретную сетку здания/специалиста и параметры владельца) и копирует общие параметры (баф, тип поиска, задержка).

- **FR-6: Наглядный UI список выбранных целей**
  - В форме конструктора до добавления шага отображается список выбранных объектов в виде чипов/карточек с иконкой, именем, локацией (`Мой город` / `Друг: Ник`) и кнопкой удаления `✕`.
  - Отображается счетчик выбранных элементов.

---

## Инварианты (INV)

- **INV-1**: Формат хранения и выполнения задач в базе данных (`scheduled_tasks.payload.actions`) не меняется. Каждое действие в `actions` является атомарным (одно здание / один специалист).
- **INV-2**: Исполнитель задач (`TaskExecutionService`) и контроллер (`ScheduledTaskController`) работают без модификации логики выполнения.
- **INV-3**: Существующие сохраненные задачи читаются и редактируются без сбоев.

---

## Acceptance Criteria (AC)

1. **AC-1**: Пользователь может открыть модальное окно зданий, отметить 3 своих здания и 2 здания друга, после чего в форме отображаются 5 выбранных целей.
2. **AC-2**: При клике на "Добавить шаг" создается 5 независимых шагов в конструкторе серии с одинаковым бафом и указанной задержкой.
3. **AC-3**: Пользователь может удалить любое из выбранных зданий из списка чипов до нажатия "Добавить шаг".
4. **AC-4**: При выборе действия со специалистом пользователь может отметить 4 геологов, нажать "Добавить шаг" и получить 4 действия отправки геолога.
5. **AC-5**: Одиночный выбор бафа сохраняется — при выборе нового бафа он заменяет ранее выбранный.
