# SDD: Приключения, бафы и постройки как отдельные лоты рынка

- **Статус:** Ready for implementation (этап 0 содержит один нежёсткий блокер — см. `implementation-plan.md`)
- **Версия пакета:** 1.0
- **Проект:** Laravel 12 / Vue 3 (TSO Manager Admin), PHP ^8.5
- **Компоненты:** Market sync (парсер лотов), Market read (каталог, аналитика, арбитраж), слой локализации, SPA рынка
- **Ключ фичи:** `market-tradeables`

## Проблема в одном абзаце

В игре лот рынка может предлагать (или требовать) не только ресурс, но и **баф**,
**приключение** или **постройку**. Тип лота передаётся отдельным полем
`dTradeObjectVO.type` (перечисление `TRADE_TYPE`), а строка `offer` кодирует
каждую сторону лота **по-разному** в зависимости от этого типа. Наш парсер
`MarketOfferParser` поле `type` игнорирует и разбирает обе стороны как ресурс
`имя,количество`. Из-за этого:

1. Лоты с бафами и приключениями **молча выбрасываются** (количество получается
   `0`, срабатывает `continue`) — поэтому «бафов вообще не видно»;
2. Те лоты, что всё же доезжают, получают `item_id = "Adventure"` — один
   псевдоресурс на **все** приключения, без перевода, потому что имя ищется
   только в секции локализации `RES`, где ключа `Adventure` нет вообще;
3. Каталог, аналитика, арбитраж и графики строятся по этому склеенному
   `item_id`, то есть считают статистику по «среднему приключению».

Полный разбор с цитатами кода игры — `data-sources.md`.

## Что делает эта фича

- Вводит понятие **tradeable** (торгуемая сущность) с явным видом:
  `resource` | `buff` | `adventure` | `building`.
- Декодирует строку `offer` строго по правилам клиента игры, с учётом `type`.
- Даёт каждому приключению/бафу/постройке **собственный** `item_id`
  (`adventure:MadHenry`, `buff:FillDeposit:Fish`, `building:Mayorhouse`).
- Локализует имена по правильным секциям (`ADN` для приключений, `BUI` для
  построек, `RES` для бафов) — ровно так, как это делает клиент игры.
- Прокидывает вид лота в API, фильтры и SPA, не ломая существующее поведение
  для ресурсных лотов.

## Краткая суть для нетерпеливых

| Что | Значение |
| --- | --- |
| Строка лота | `<offerSide>\|<costSide>\|<totalLots>` — **ровно 3 сегмента** |
| Кто решает формат стороны | `dTradeObjectVO.type`: 0 res/res, 1 res/buff, 2 buff/res, 3 buff/buff |
| Ресурсная сторона | `name,amount` |
| Бафовая сторона | `buffName,resourceName,amount[,recurringChance]` |
| Приключение | баф с `buffName = "Adventure"`, `resourceName = <имя приключения>` |
| Постройка | баф с `buffName = "BuildBuilding"` / `"BuildDefenseModeBuilding"` |
| Запрос без цены | `costSide == "@"` → цены нет (сейчас такие лоты просто отбрасываются) |
| Секции локализации | приключение → `ADN`, постройка → `BUI`, баф → `RES` |
| Главный виновник | `app/Services/Market/Sync/MarketOfferParser.php` (строки 40-70) |
