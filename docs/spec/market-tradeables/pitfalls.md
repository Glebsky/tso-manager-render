# Pitfalls: ловушки, на которых точно можно упасть

> Прочитать ПЕРЕД написанием кода и ещё раз перед коммитом.

## Парсинг

**P-1. `(int) "MadHenry" === 0`.** Именно это убивает бафовые лоты сейчас.
Никогда не приводи сегмент к int без `ctype_digit`. Используй приватный
`parseAmount(?string): ?int`, возвращающий `null` на мусор.

**P-2. Отрицательные числа.** `ctype_digit("-5")` возвращает `false`. Это НАМ НА РУКУ:
отрицательные количества на рынке невалидны. Не переделывай под `is_numeric`,
иначе пролезут `"1e3"`, `"0x10"`, `" 5 "`.

**P-3. `count($parts) < 2` вместо `!== 3`.** Текущая ошибка в коде.
Клиент требует ровно 3 сегмента.

**P-4. Баф без субъекта даёт ПУСТОЕ второе поле**, а не отсутствующее:
`"ProductivityBuffLvl3,,1"`. `explode` даст `["ProductivityBuffLvl3", "", "1"]`.
Пустая строка → `subject = null`, а не `""`.

**P-5. Бафовая сторона может быть всего из 2 полей.** Тогда `amount`
клиент берёт из определения бафа. У нас определений бафов в рантайме нет,
поэтому ставим `rawAmount = null`, а `units = 1` (ADR-5). НЕ считай это ошибкой
разбора.

**P-6. Лишние пробелы.** Клиент делает `StringUtil.trim` только для
`totalLots`, но безопаснее `trim()` каждый сегмент перед анализом.

**P-7. Неизвестный `type`.** Любое значение вне 0..3 НЕ должно бросать
исключение и ронять весь синк. Лот пропускается, счётчик `unparsed` +1.
`MarketItemKind::tryFrom` вместо `from`.

**P-8. `type` может прийти строкой.** `parse_market.py` отдаёт то, что было в AMF;
AMF-целое может десериализоваться как `int`, `float` или строка. Всегда
`(int) ($raw['type'] ?? -1)` с проверкой диапазона. То же для `slotType`.

**P-9. Отсутствие `type` НЕ равно 0.** Если поля нет вообще — это аномалия
транспорта, логируем и пропускаем. Тихий fallback на `0` вернёт текущий баг.

## Локализация

**P-10. `FillDeposit` без субъекта → ключ `FillDepositAny`.** Не `FillDeposit`.
Оба ключа есть в `lang/ru/game.php`, перепутать легко, тест обязателен.

**P-11. `ChangeColorScheme` клеится через `_`, а не через `:`.**
Ключ локализации = `ChangeColorScheme_<subject>`, но `item_id` всё равно
`buff:ChangeColorScheme:<subject>`. Не путать ключ локализации с нашим id.

**P-12. Ключа `RES.Adventure` НЕ СУЩЕСТВУЕТ.** Не пытайся его добавить в
`lang/*/game.php` вручную. Эти файлы — генерируемые, ручные правки
затрёт следующий `tso:lang:import`. Правильный путь — брать имя из `ADN`.

**P-13. Секция `ADN` не экспортируется на фронт.**
`LangFrontendExportCommand::FRONTEND_GAME_SECTIONS` = `['BUI','LAB','RES','SPE']`.
Забыть добавить `'ADN'` и перегенерировать — значит в SPA будут сырые
`MadHenry` даже при идеальном бэкенде.

**P-14. `lang/uk/game.php` почти пустой (5.8 КБ против 7.38 МБ у ru).**
Все тесты локализации пиши на `ru` или `en`. На `uk` обязан fallback,
а не исключение.

**P-15. Плейсхолдеры `{0}` и `{1,RES}`.** Значения бафов в `RES` содержат
шаблоны. Если не передать `[amount, subject]`, в UI попадёт литеральное `{0}`.
См. `GameTranslationResolver`, `MAX_PLACEHOLDER_DEPTH = 3`.

**P-16. Не передавай композитный id в резолвер как ключ.**
`RES."buff:FillDeposit:Fish"` не существует. Композитный id СНАЧАЛА
разбирается `TradeableIdFactory::parse()`, потом резолвится имя.

## База данных и запись

**P-17. `string(100)` мал для композитных id.** Обязательно расширить до
`191` в той же миграции, иначе получишь обрезанные id или ошибку вставки
на проде.

**P-18. Забыть новые колонки в `$updateColumns` персистера.**
`MarketOfferPersister` делает `MarketOffer::upsert($chunk, ['server_id','offer_id'], $updateColumns)`.
Если `item_kind` не в `$updateColumns`, то новые значения пишутся только при
вставке и НИКОГДА не обновляются — баг проявится только на втором синке.

**P-19. Не трогать `unique(['server_id','offer_id'])`.** Он был починен отдельной
миграцией `2026_07_22_150000_fix_market_offers_unique_constraint.php`. Любое
вмешательство ломает upsert для мультисерверного режима.

**P-20. `market_history` не имеет `sender_name` и `lots_remaining`.** Не копируй
слепо список колонок из `market_offers`.

**P-21. `price` стал nullable — проверь ВСЕ агрегаты.**
`avg`, `min`, `max` в Postgres игнорируют NULL, но `MarketHistoryAggregator`,
`LoopArbitrageFinder` и `MarketAnalyticsService` могут делить на count(*).
Добавь `whereNotNull('price')` в каждом месте (ADR-6).

**P-22. Фильтр `kind` меняет ключи кэша.** `MarketCacheService` и TTL из
`config/market.php` (`goods`, `targets`, `popular`, `analytics_*`, `arbitrage`).
Если не включить `kind` в ключ кэша, пользователь будет видеть чужой вид
лотов до 30 минут.

## Общие правила проекта, которые легко нарушить

- `declare(strict_types=1);` в каждом новом PHP-файле.
- Классы сервисов — `final readonly`, зависимости только через конструктор.
- `MarketOfferResource` использует setter-инъекцию `using(...)` и бросает
  `LogicException`, если её не вызвали. Добавляя поля, не ломай этот контракт.
- Генерируемые файлы (`lang/*/game.php`, `resources/js/lang/generated/*.json`,
  `config/game_tradeables.php`) руками НЕ правятся — только командой.
- `docs/references/**` — только чтение. Запрещено править и удалять.
