# Requirements: Upgrade to PHP 8.5

- **Пакет:** php-85-upgrade v1.0
- **Статус:** Draft / Planning

## 1. Введение и Цель

Целью данной задачи является перевод проекта TSO Manager с PHP 8.4 на PHP 8.5 для получения преимуществ обновленной среды исполнения (повышение производительности, улучшенная статическая типизация, новые возможности синтаксиса и исправления безопасности).

## 2. Функциональные Требования

### REQ-001: Обновление Runtime Contract
- Среда исполнения PHP проекта должна быть явно переведена на версию `^8.5`.
- Значение `config.platform.php` в `composer.json` должно быть установлено в `8.5.0`.
- В `docs/spec/constitution.md` (Раздел 3 "Runtime Contract") значение допустимой версии PHP должно быть обновлено с `^8.4` на `^8.5`.
- В `AGENTS.md` стек проекта должен указывать `PHP 8.5`.

### REQ-002: Обновление Docker-окружения
- Базовый Docker image в `Dockerfile` должен использовать `php:8.5-fpm-alpine`.
- Все необходимые системные расширения (`pdo`, `pdo_pgsql`, `pdo_sqlite`, `zip`, `redis`) должны корректно собираться и работать в среде PHP 8.5 Alpine.
- Скрипты инициализации и конфигурации PHP-FPM (`docker/php/php.ini`, `docker/php/www.conf`) должны оставаться полностью совместимыми без синтаксических ошибок или устаревших директив.

### REQ-003: Совместимость зависимостей Composer
- Все зависимые пакеты (`laravel/framework ^12.0`, `laravel/sanctum ^4.0`, `guzzlehttp/guzzle`, `larastan/larastan`, `phpstan/phpstan`, `phpunit/phpunit`, `laravel/pint`, `spatie/laravel-ignition`) должны поддерживать PHP 8.5.
- В случае необходимости версии пакетов в `composer.json` должны быть минимально обновлены до стабильных релизов, поддерживающих PHP 8.5.

### REQ-004: Устранение устаревших механизмов (Deprecations)
- Исходный код приложения (`app/`, `config/`, `database/`, `routes/`, `tests/`) не должен содержать синтаксиса, функций или методов, объявленных устаревшими (deprecated) в PHP 8.5.
- Никакие системные предупреждения `E_DEPRECATED` или `E_USER_DEPRECATED` не должны замусоривать логи приложения во время выполнения тестов или стандартной работы.

### REQ-005: Применение возможностей PHP 8.5
- Использование новых возможностей синтаксиса PHP 8.5 разрешено и рекомендуется там, где это сокращает шаблонный код и повышает читаемость (по аналогии с RFC о property hooks и асимметричной видимости в 8.4).
- Массовые точечные рефакторинги без необходимости запрещены (согласно Конституции).

## 3. Нефункциональные Требования

### NFR-001: Безопасность и Изоляция (Single-Operator Invariant)
- Переход на PHP 8.5 не должен изменять или ослаблять ограничения безопасности, описанные в ADR-001 и `constitution.md`.
- Запрещено изменять логику работы сессий, Sanctum-аутентификации, шифрования кредо или изоляции учетных записей TSO.

### NFR-002: Производительность и Стабильность
- Время выполнения тестовой suite не должно увеличиваться.
- Потребление памяти Docker-контейнерами в режиме FPM не должно возрастать по сравнению с PHP 8.4.

### NFR-003: Детерминированность сборки
- Образы Docker должны собираться без ошибок и депрекейшенов во всех стадиях (`base`, `vendor-builder`, `development`, `production`).

## 4. Ограничения (Constraints)

1. Запрещено модифицировать файл `.env` или секреты окружения.
2. Изменения должны быть точечными и обратимыми.
3. Все 4 гейта качества (`php artisan test`, `./vendor/bin/pint --test`, `./vendor/bin/phpstan analyse`, `npm run build`) должны успешно проходить.

## 5. Критерии Приемки (Acceptance Criteria / DoD)

- [ ] В `composer.json` указаны ограничения `php: ^8.5` и `platform.php: 8.5.0`.
- [ ] В `Dockerfile` используется образ `php:8.5-fpm-alpine`.
- [ ] Файлы `AGENTS.md` и `docs/spec/constitution.md` обновлены с указанием версии `PHP 8.5`.
- [ ] Команда `php artisan test` выполняется с нулевым кодом возврата (100% прохождение тестов).
- [ ] Команда `./vendor/bin/pint --test` не выявляет ошибок форматирования.
- [ ] Команда `./vendor/bin/phpstan analyse` завершается успешно без ошибок на уровне 6.
- [ ] Сборка фронтенда `npm run build` проходит без ошибок.
- [ ] Docker-контейнеры поднимаются и проходят healthcheck без ошибок в логах PHP-FPM.
