# SDD: Очередь производства бафов (`produce_buff`)

- **Статус:** Ready for implementation
- **Версия пакета:** 2.0 (все утверждения сверены с живым трафиком)
- **Проект:** Laravel 12 / Vue 3 (TSO Manager Admin), PHP ^8.5
- **Компонент:** Task Planner, TSO AMF protocol layer, Zone snapshot
- **Новый тип задачи:** `produce_buff`

## Назначение

Оператор выбирает здание-производитель (Дом снабжения, Переплётчик,
Лаборатория и др.), выбирает рецепты бафов, указывает количество, видит
суммарную стоимость в товарах и время, добавляет шаги в `sequence` и
выполняет их как обычную задачу планировщика по расписанию.

Важно: это **очередь внутри здания**, НЕ общая очередь строительства. В игре
это две независимые подсистемы с разными командами и разными структурами
в снапшоте зоны.

## Краткая суть для нетерпеливых

| Что | Значение |
| --- | --- |
| Команда игры | `COMMAND.START_TIMED_PRODUCTION = 91` |
| Payload | VO `defaultGame.Communication.VO.dTimedProductionVO`, **14 полей в точном порядке** |
| Обёртка | нет `dServerAction`; VO лежит в `dServerCall.data` напрямую |
| **НЕ** использовать | `CMD_STOP_PRODUCTION = 107` — тумблер вкл/выкл, не очередь |
| Где очереди в снапшоте | `zone.timedProductions_vector` — массив `ArrayCollection` |
| Как найти свою очередь | по `items[0].productionType`, **НЕ по индексу массива** |
| Каталог зданий | `docs/references/icons.xml`, атрибут `productionType` у `<Building>` |
| Каталог рецептов | `docs/references/globals.xml`, `<Buff produceable="true">` + `<TimedProductionList>` |
| Стоимость | `<Costs><Cost name count/></Costs>` × `amount` × `stacks` |
| Лимиты | `amount` 1..25, `stacks` 1..200 (UI v1 — только `stacks=1`) |
| Новый тип задачи | `TaskType::ProduceBuff = 'produce_buff'` |

## Ключевые решения (кратко)

- **Очередь производства ≠ очередь строительства** (ADR-1). Разные команды,
  разные классы, разные места в снапшоте (`timedProductions_vector` против
  `buildQueue`).
- **Очередь ключуется по `productionType` в пределах зоны**, а не по зданию
  (ADR-2). Это контринтуитивно и доказано три раза независимо, в том числе
  `buildingGrid = 0` у живого заказа в снапшоте. Два одинаковых здания
  делят одну очередь — оператора надо предупреждать (FR-11).
- **Одна команда несёт `amount`**, поэтому «10 бафов» — это ОДНО действие
  sequence с `amount: 10`, а не 10 шагов (ADR-3-R). Отличие от `collect_building`
  ADR-9 и `build-mine` ADR-6 — обоснованное.
- **Каталог — в конфиге, генерируется artisan-командой** из игровых XML
  (ADR-5). Не опция, а необходимость: в снапшоте зоны у здания НЕТ поля
  `productionType`.
- **Стоимость — снапшот в `meta`**, не пересчитывается при исполнении (ADR-6).
- **Отказ из-за занятой очереди — успешный исход задачи**, а не исключение
  (ADR-7), по образцу `build-mine` ADR-12.
