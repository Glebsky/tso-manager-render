# Decisions (owner, 2026-09-25)

Решения имеют приоритет над формулировками в остальных документах.

## ADR-001 — Stop прерывает только текущий запуск (OQ-001)

- «Stop» переводит задачу в `cancelled` и прерывает выполнение.
- Расписание сохраняется: периодическая (`daily`, `interval`) задача с `is_active=true` снова
  резервируется в свой следующий слот. `cancelled` не терминален.
- Снятие с расписания делается только через toggle (`is_active=false`).
- Once-задача после Stop повторно автоматически не выполняется (у неё нет следующего слота).

## ADR-002 — Пропущенные слоты пропускаются (OQ-002)

- Если планировщик не работал в момент слота, задача **не догоняет** пропущенный запуск.
- Слот считается «вовремя», если тик произошёл в пределах окна
  `config('game.scheduler.missed_grace_minutes')` (по умолчанию `5`) после `next_run_at`.
  Окно нужно, потому что тик раз в минуту и `withoutOverlapping` может сдвинуть его.
- Позже окна: запуск не выполняется, `next_run_at` сдвигается на следующий будущий слот,
  пишется `last_result = [Skipped] missed slot <время>` и запись в activity log (`warning`).
- Поведение по типам:
  - `daily`: следующий `run_at_time` в будущем.
  - `interval`: `now + interval`. *(Предположение A-1, см. ниже.)*
  - `once`: задача не выполняется, `is_active=false`, `status=failed` с причиной «missed». *(Предположение A-2.)*

## ADR-003 — Интервал отсчитывается от окончания прошлого запуска (OQ-003)

- `next_run_at = finished_at + interval`, где `finished_at` — момент записи финального статуса
  (`completed`/`failed`/`cancelled`).
- Дрейф на длительность выполнения — **ожидаемое поведение**, дефектом не считается (A-10 переклассифицирован).
- Остаётся дефектом и исправляется: округление `(int) diffInMinutes()` + `abs()`
  (задача может стартовать до минуты позже) — сравнение ведётся по `next_run_at <= now`
  с точностью до секунды.
- Колонка `scheduled_for` не вводится (KISS): база интервала — окончание запуска.

## ADR-004 — Поддерживаются оба варианта развёртывания (OQ-004)

| Режим | Кто исполняет джобы | Ограничения |
| :--- | :--- | :--- |
| Docker (`scheduler_mode=queue`) | Долгоживущий `worker` по всем очередям `tso-*` и `default` | `pcntl` в образе, `$timeout` применяется |
| OSPanel / cron (`scheduler_mode=cron`) | Встроенный воркер `tso:run-scheduler --work` раз в минуту | Нет `pcntl` на Windows: `$timeout` джобы не применяется, защита — `http_timeout` и бюджет джобы; задержка старта до 60 с |

- Список очередей берётся из одного источника (`config('game.queues')`) в обоих режимах.
- Инвариант `retry_after > timeout + margin` обязателен для обоих режимов.
- Тесты покрывают оба режима на уровне команды `tso:run-scheduler`.

## Предположения, ожидающие подтверждения

- **A-1**: для `interval` пропущенный слот означает «следующий запуск через полный интервал от сейчас».
  Альтернатива — считать, что у interval-задачи пропусков нет, и запускать её сразу после восстановления.
- **A-2**: пропущенная `once`-задача помечается `failed` («missed») и не выполняется.
  Альтернатива — выполнить её один раз с опозданием.
- **A-3**: окно `missed_grace_minutes = 5`.

### Статус предположений (2026-09-25, WP-06)

WP-06 реализован **по дефолтам A-1…A-3**, чтобы не блокировать спецификацию. Подтверждение владельца
по-прежнему требуется; каждое изменение локализовано:

| Предположение | Где реализовано | Как изменить |
| :--- | :--- | :--- |
| A-1 (interval → `now + interval`) | `ScheduleCalculator::nextFutureSlot()` | вернуть `now` для `Interval` (задача запустится на ближайшем тике) |
| A-2 (once missed → `failed`, `is_active=false`) | `TaskStateMachine::skipMissedSlot()` (ветка `$isOnce`) | не вызывать `skipMissedSlot` для once в `processDueTasks()` — тогда она выполнится с опозданием |
| A-3 (grace = 5) | `config('game.scheduler.missed_grace_minutes')`, env `TSO_MISSED_GRACE_MINUTES` | изменить env, код не трогать |

Побочное следствие A-1, на которое стоит обратить внимание владельца: раньше interval-задача,
включённая после долгой паузы, стартовала на ближайшем тике; теперь — через полный интервал
от момента включения (`toggle()` → `scheduleRunAt()`).
