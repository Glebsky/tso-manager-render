## 1. Контекст и постановка задачи

Панель управляет игровыми аккаунтами The Settlers Online через AMF-вызовы. Чтобы вызов прошёл, нужны:

1. `dso_auth_user` + `dso_auth_token` — веб-токены, полученные со страницы `play` сайта игры;
2. `bb_url` — адрес Load Server (балансировщика) для региона;
3. живые cookies домена игры (файл `storage/app/cookies/account_{id}.txt`);
4. резолвнутый endpoint AMF-сервера + `DSId` игровой сессии.

**Наблюдаемая проблема:** авторизация выполняется слишком часто (фактически «на каждую задачу»), задачи периодически падают с игровыми ошибками `1005` (сессия истекла) и `1012` (обнаружена более новая сессия), а восстановление всегда происходит **постфактум** — после провалившегося вызова.

**Цель:** привести поведение к эталону C#-клиента: одна долгоживущая сессия переиспользуется всеми процессами; полный логин выполняется **только** когда сессия действительно мертва; протухание определяется одним дешёвым запросом, а не 40-секундным таймаутом.


## 2. Область работ

### 2.1. В области (In scope)

1. Общий кэш игровой сессии между web / queue worker / scheduler (Ф0).
2. Полное удаление отладочных дампов `storage/app/debug/play_page.html` и `storage/app/debug/flash_vars.json` (Ф1).
3. Дешёвая проверка живости сессии перед работой и единая точка входа авторизации (Ф2–Ф4, Ф7).
4. Скользящий TTL игровой сессии (Ф5).
5. Память о том, какая ветка логина сработала (Ф6).
6. Тесты и документация (Ф8, Ф9).

### 2.2. Вне области (Out of scope)

См. [quickstart.md](quickstart.md). Кратко: 2FA/TOTP, капча, `zone_id`, миграции, смена HTTP-клиента, фронтенд.
